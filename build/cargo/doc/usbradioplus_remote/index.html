Crate usbradioplus_remote

Source
Expand description

Thin dynamically loaded C clients. Radio policy remains in the remote-base DSO; no Hamlib types, devices, sockets or controller implementation are embedded here.

Modules§

  • raw
    Installed C records. Their layout comes from the published development headers.

Structs§

  • CallError
    Preserved dependency status, without secret-bearing transport values.
  • HamlibOperating
    One creating-thread-owned Hamlib rig used by the shared physical service. This translates complete engine states, not another tune/scan state machine.
  • HamlibProvider
    Loaded Hamlib dependency adapter. Parallel and ordinary radios do not load it.
  • HamlibRig
    One rig retained on its creating physical worker. NonNull intentionally prevents moving it to another thread; the provider outlives destruction.
  • RemoteProvider
    Loaded portable operating engine. Load only for an enabled remote composition. Retain this owner until all contexts and callbacks have been destroyed.
  • RemoteSession
    One physical owner’s remote state machine. The opaque handle is deliberately not Send; create, service, retire and destroy it on that same worker.
  • SelectedCapabilities
    Actual capabilities assembled from the selected dependency and DSP/GPIO owners. These records carry no device handle, borrowed string, or operating policy.
  • Setting
    One owned adapter-neutral operating capability.

Enums§

  • ProviderError
    Provider load or contract-admission failure; no device has been opened.

Traits§

  • OperatingIo
    Synchronous operations supplied by one existing non-audio physical owner. The dynamic engine owns all tune/scan policy. Calls must not reenter it; audio/control callbacks never implement or invoke this interface.

Functions§
